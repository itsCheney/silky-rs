# 景の海のアペイリア ～カサブランカの騎士～

[English](casablanca.md) | 简体中文

《景の海のアペイリア》的粉丝光盘。日文版（SILKY'S PLUS WASABI，2017）。运行时根据目录中的 `casablanca.exe` 识别这个游戏；本页所述版本的 SHA-256 为 `4865b23597087c03a4dd7017ced9e5c48e8d4479c923705cd41bd91b4246d716`。程序版本 1.0.0.0，2017-12-10 链接。引擎配置：[engine-2017](../builds/engine-2017.zh-CN.md)。

它运行在 Apeiria 模块上。程序和 `apeiria.exe` 出自同一份代码：4643 个函数中有 4049 个能对上，其中 3959 个完全相同。引擎类、`Game` 分派、标题菜单、消息窗口、αMAIL、全息面板和血条都是同一份代码，所以 [Apeiria 页面](apeiria.zh-CN.md)上写的内容在这里同样适用，不再重复。本页只列出不同之处。

脚本：`FD0101` 到 `FD4102`（剧情）、`FD_SCENE_01` 到 `FD_SCENE_14`（场景回想）、`MAIN`、`START`、`OMAKE`、`SCMODE`、`FLAGINI`。脚本编译时在语句之间带有调试行标记（`dbg.line`、`dbg.call`），消息的文字在显示它的调用之前一行压栈（在 `main.inc` 宏里的 `BackLog.3`）。VM 把压在调试标记之前的消息文字算作下一个引擎调用的一部分；这是为这个游戏加的。

每条路线结束后，剧情都会回到发邮件的选项（沙羅へメールを送る、七海へメールを送る）；两条都读完后进入最后一章。无头运行 `silky-run snap --path 0,1` 会依次跑完两条路线和最后一章，直到片尾影片并回到标题，所有引擎调用和 `Game` 调用都会执行。第一句话的画面和 Wine 下的原版一致，整个剧情（在原版 Wine 下做同样的两次邮件选择，用 `silky-run snap --path 0,1 --xml /Config/Movie/Play=0` 运行到标题，共 15,103 行）的引擎调用与原版一致，但有两处例外：下文说明的重复名字和语音调用，以及标题第一个声音（`seg_000?.wav`）的随机选取。重复的调用是：原版在 `MesWnd.3` 之后会把有语音那句的名字和语音调用（`BackLog.2` 与 `BackLog.3` 之间的那些）再执行一次。引擎把这些调用记作这句话的回想记录：`BackLog.2` 开始记录，之后执行的每条脚本指令都追加进去，直到 `BackLog.3`；回想里重播语音时会再执行这份记录。位置在代码里找到了：`MesWnd.3` 设置这一句时，消息窗口会再执行一次这句的回想记录，并带上一个标志，让文字指令只按行统计字数而不绘制（即量一遍这句话）。记录里的名字和语音调用会再执行，只是因为原生调用不检查这个标志。它们把同样的名字和语音再设置一次；语音在 `MesWnd.3` 时已经开始播放，所以画面和声音都没有变化，运行时只执行一次。打开跳过场景（`/Config/SceneSkip`，0x5308f8）且这句已读时不会执行第二遍：这句的设置函数（0x466120，0x466164 处）在再次执行记录之前读取该配置和这句的已读标志；运行时本来就不会执行第二遍。该对比中影片是关闭的，因为原版在 Wine 下的配置中 `/Config/Movie/Play` 为 0；将其设为 1 后，脚本会播放 `matrix.vsd` 及其他影片，而原版显示的是它们的 akb 动画。运行时的默认值是 1，与可执行文件自己的默认值一致：所有读取 `/Config/Movie/Play` 的地方都调用 XML 读取函数（0x4ca8e0，节点不存在时返回调用者给的默认值），默认值都是 1（影片对象的 0x42c1e3、0x42c306、0x42c509；配置对象的载入 0x496b02，它把值放在一个字段里，0x496eb4 的保存函数再写回）。程序里没有任何地方把它设成 0：这个字符串只有这五处引用，也没有代码往那个字段存 0；脚本从不碰它（整段剧情的轨迹里只有对 `/Config/OneMes` 和 `/Config/AutoRead` 的 `Xml.1`），影片无法播放时也不会写它。所以 Wine 文件里的 0 不是引擎写的。没有配置文件时原版在标题之前出错，原因是 `start.mes` 的第一个 `Xml.1`（`/Config/OneMes`）没有可写入的树：文件打不开时载入函数（0x4ca3d0）让根节点保持为空，按路径写入的函数（0x4caea0）随后把第一个节点挂到这个空根上，读了空指针偏移 0x50 处（0x4cb1be：访问地址 0x00000050 的页错误）。在空树上读取没有问题（返回默认值）。所以缺文件会崩溃是预期的；引擎不会自己创建它，也没有内置副本。`Save/` 下的文件是游戏目录里 `FileInfo.xml` 的副本，末尾加上引擎的 `<Config>`；程序期望安装程序把它放好（`Save` 文件夹旁的 `<名称>_inst.xml`，即 `/InstallSetting/InstallPath` 和 `/InstallSetting/RunExe`，也会被载入，但通过配置指针没有任何地方读它；安装程序复制 `FileInfo.xml` 这一点是从文件内容推断的，代码里没有）。其他设置的首次默认值同样来自代码，例如消息窗口的颜色 (0, 25, 46) 和透明度 30（0x496a0b 起）。

## 与 Apeiria 的不同

### 特效

大多数特效看起来一样。许多淡入改成了通过规则图片的擦除，淡出仍是淡出。

特效在剧情中的八处与 Wine 下运行的原版逐帧对照过：`Game.1001` 子命令 1 和 2、巨龙与攻击 18、`Game.12` 的插图、两种不透明度下的 `Game.13` 子命令 12，以及最后一章前的雪花屏。经过两处修正后都一致：立绘擦除的软边，以及再次显示同一角色时的不透明度（见下）。

- 放大闪光（`Game.1005`）：打开跳过场景的设置时，原版什么都不做（没有放大、闪光或淡入）；关闭时与 Apeiria 的放大和白色闪光相同。这里没有提供该设置，除非脚本写入 `/Config/SceneSkip`（脚本不会写），否则按关闭处理。
- 用擦除代替淡入：攻击种类 1 到 5、13 和 15；法术子命令 4 和 9；`Game.1001` 子命令 1、3、14、15 和 20。每个都用自己的规则图片，与可执行文件一致。
- 立绘擦除（攻击、法术、`Game.1001`）的软边宽 255 个规则级：擦除进行到某像素的规则值时它开始出现，再过 255 级完全显示。这是在原版画面上测出的；运行时的其他擦除仍是 32 级。
- αMAIL（`Game.1012`）：子命令 1 与 Apeiria 是同一段代码。它对面板的精灵做一次通过规则图 46 的擦除，共 64 帧（标志 0x2000102，帧数 0x40，规则 0x2e），并等它结束；引擎处于跳过状态时直接显示面板。50 颗光点也相同（0x47ba10, 0x47bc10, 0x47bd20, 0x47bf10：50 颗，每颗 8 帧，最后 8 帧不再发出，重新出发的带为 y 20 到 479）。不同于运行时原先的 Apeiria 擦除的是擦除的步进（0x4c3880，在 0x4c3190 里设置）：规则值为 r 的像素，不透明度是 `min(自身不透明度, 级别 - r)`，级别每步增加 `512 / (帧数 - 1)`，从 0 走到 512，所以软边缘宽 255 级（与其他精灵擦除一样），面板在第 63 步就完整了，比动画结束早一帧。因此半透明的玻璃会先于不透明的列表达到自己的不透明度。运行时对 Casablanca 这样做（`Canvas::blend_capped`）；Apeiria 的可执行文件里擦除步进是否相同，这里没法核对（没有 `apeiria.exe`），Apeiria 仍用 32 的边缘，只是它等待的最后一帧现在是完整的面板。
- 攻击种类 18（`Game.998`）：一道火柱（`attack_17_00.akb`）从上方落下，然后擦除消失。脚本会等到它结束。
- 攻击种类 14 带一个参数：0 显示全部十张图片，1 显示前五张，2 显示后五张。
- `Game.998` 的子命令大于 4 时什么也不做（脚本里有两处调用）。
- `Game.13` 子命令 12（透明度、时间、大小、名字、位置）：以某个不透明度显示立绘角色，但只有新角色才采用这个透明度。如果该位置上已经是同一个角色，只换新的图片和大小，保持原来的不透明度，不使用这次的透明度值（0x44b4e0）。两个名字在可执行文件给出相同编号时算同一个角色（0x44e0a0）：名字必须以 `ch` 开头，随后 `01` 到 `07` 得 0 到 6，`09` 得 7，`10` 得 8；其他情况（`ch00`、`ch08`、`ch11` 及以上、不以 `ch` 开头、不足四个字符）得 -1。只读前四个字符，所以 `ch01_a` 和 `ch01_b` 是同一个角色，两个都得 -1 的名字也算同一个角色。运行时使用同一个编号。正常通关时到达这个调用的脚本只用 `ch09` 和 `ch10` 作为身体名。
- `Game.10` 子命令 14 是启动时的调用，不需要做什么。
- 推理板（`Game.994`）：与 Apeiria 相同（子命令 2 从中间一条线打开，3 关闭，5 缩放一个标记），只有子命令 4 不同：新图在 24 帧内通过规则 1 擦除显示，Apeiria 里是淡入。脚本会等每个动画结束（打开、关闭、换图 24 帧，标记 12 帧），点击不会缩短。`/Config/SceneSkip` 为 1 时，引擎完全跳过子命令 0、2、3、4、5，运行时也一样。剧情脚本只在启动时关闭并撤掉推理板。
- `Game.991`：Casablanca 从不显示这块面板。它是 Apeiria 的说明幻灯片面板，留在了引擎里：Casablanca 的数据里没有它的图片（`tbg.akb`、`wbg.akb`、`t*` 和 `w*` 幻灯片），脚本只在启动时调用它的子命令 1（销毁，而此时没有东西可销毁），能重建它的读档代码读取一个存档值，Casablanca 从不写入这个值。它的子命令 3（通过规则图擦除显示）没有调用者。
- 结论列表（`Game.992`）：格子从 1 开始计数，所以值 `v` 对应的格子是第 (v - 1) / 100 列、第 (v - 1) % 100 行。

### 鉴赏模式

- CG 鉴赏：5 页，每页 3 x 3 格，43 个条目，243 张图片。条目内的图片网格仍是每页 12 格。条目按表中顺序排列，不是按图片排序；图片的已看标记位也不一定等于它所在的行（插在以 `cg_ev1209.akb` 开头的 16 张图片条目里的两张图片，标记位是 241 和 242）。CG 记录器除了 `ev...` 之外，也保留名为 `cg...` 的背景。
- 场景回想：14 个场景，每页 3 x 2 格，3 页，已看字节 3101 到 3114。播放场景时运行 `FD_SCENE_NN.MES`。
- 音乐鉴赏：32 首 `.wav`，8 行；已听字节不按行顺序排列。鉴赏模式播放 `casablanca_shortinst.wav`。
- 滚动条、页码按钮和方向键都按新的数量处理。CG 画面里从“下一页”箭头按上键哪里也不去，与原版一样。
- 两部作品都不会在两次打开之间记住任何东西。每次打开 CG、场景或音乐画面（包括在三个模式之间切换）都从第一页（音乐是列表顶部）开始。页码、场景页和滚动位置只存在于画面自身。CG 画面打开时唯一会读取的，是游戏状态记录里的一个标志和一个起始图片编号（页码为该编号除以 16）；脚本从不设置它，所以不会生效。

### 声音

`HEffect`（类 17）与 `Effect`（类 16）使用相同的子命令：两者走同一份声音对象代码（0x4adc70，`Effect`、`HEffect`、`Voice` 共用 0x4add34 处的一张跳转表）。区别在于各自的方法表和读取的配置。`Effect` 的对象在 0x49fca3 构造，方法表 0x52ea14，通道列表由 0x4ae700 生成；`HEffect` 的在 0x49fcdc 构造，方法表 0x52b758，通道列表由 0x4ae9c0 生成。`HEffect` 是另一组独立的音效通道，不是同一批通道：在 `HEffect` 通道 0 上开始的声音不会顶替 `Effect` 通道 0 上的声音。它读取 `/Config/HEffect/Error`、`/Config/HEffect/Enable` 和 `/Config/HEffect/Volume`（0x53074c、0x530764、0x53077c；音量默认 90，再乘主音量，见 0x4950f0）。游戏里没有任何画面设置这些值，所以音量保持 90，声音开启。运行时为 `HEffect` 设了单独的总线（音量为主音量的 0.9 倍，不受音效音量设置影响），停止所有声音时也会停掉它。

### 制作人员名单和结局图片

制作人员名单是 `Game.990`（分支在 0x48d8f4，处理函数 0x492160）；脚本在最后一章之后用子命令 0、不带参数调用它。它是一个独立的面板，不是脚本摆出的图片：处理函数构造一个面板对象（虚表 0x530100，构造函数 0x480a80），一次性载入它的图片（0x480c50：`ending.akb`、`staff.akb`、`staff00.akb`、`staff05.akb`、`staff03.akb`、`bcg99.akb`），运行一个循环（0x4a8780），同时由一个线程（0x481040）每个节拍调用面板的更新函数（0x4810f0），结束时把图片撤掉（0x480e20）。更新函数从开始计时，到 105,000 毫秒（0x19a28）时停止面板。画在当时屏幕上的画面之上：

| 时间（毫秒） | 内容 |
| --- | --- |
| 700 到 5,033 | `ending.akb` 淡入，并保持到结束 |
| 5,033 到 6,033，淡出 8,033 到 9,000 | `staff00.akb` 淡入、停留、淡出 |
| 10,366 到 11,333，淡出 13,366 到 14,333 | `staff05.akb` 淡入、停留、淡出 |
| 16,033 到 97,866 | `staff.akb`（1280 x 2640）沿直线从 y = 720 升到 y = -2640 |
| 97,700 到 99,666，淡出 102,700 到 105,000 | `staff03.akb` 淡入、停留、淡出 |
| 102,700 到 105,000 | `bcg99.akb` 在画面上淡入 |

时间和曲线都取自代码，读自更新函数（0x4810f0）和它的两个辅助函数。名单按时钟推进，而不是按帧：线程（0x481040）不断调用更新函数，两次调用之间只睡很短的时间，所有数值都由开始以来的毫秒数算出（开始时间由 0x480f10 记下）。全部是对时间的线性函数：

- 各页（0x481190，表在 0x561518，每页四个时间：淡入开始、淡入结束、淡出开始、淡出结束）：淡入透明度为 `(t - 淡入开始) * 255 / (淡入结束 - 淡入开始)`（整数）；淡出透明度为 `255 + (淡出开始 - t) * 255 / (淡出结束 - 淡出开始)`（浮点，截断为整数，不小于 0）。淡入结束到淡出开始之间不做任何设置，页面保持最后给出的透明度。淡出到 0 时载入下一页。三页是 `staff00.akb`、`staff05.akb` 和 `staff03.akb`，时间见上表（最后一行的淡出是 102,700 到 105,000）。
- 结局图片和 `bcg99.akb`（0x4812f0，表在 0x561468，每项两个时间：700 到 5,033 和 102,700 到 105,000）：透明度为 `(t - 开始) * 255 / (结束 - 开始)`，画在这一步开始时那一层内容的副本之上；透明度到 255 或时间超过结束时进入下一步。
- 长条（0x4810f0）：在 `16,033 <= t <= 97,866`（0x561510、0x561514）期间，它的 y 为 `(16,033 - t) * 3360 / (97,866 - 16,033) + 720`，其中 3360 = 720 + 2640，所以它沿直线从开始时的 720 走到结束时的 -2640，之后不再绘制。它没有透明度。
- 时间到 105,000（0x19a28，在 0x481114）时面板自己停止。

运行时按 16 毫秒一帧（`TICK_MS`）推进，并把上述每个时间各自四舍五入到最近的一帧，因此长度不会累积漂移；运行时的某一帧与原版同一时刻的值最多相差一帧的变化量（1,000 毫秒淡入淡出里约 4 级透明度，长条约 0.66 像素）。起止帧为 `round(t / 16)`：44 和 315（结局图片），315 到 377 与 502 到 563（`staff00.akb`），648 到 708 与 835 到 896（`staff05.akb`），1,002 到 6,117（长条），6,106 到 6,229 与 6,419 到 6,563（`staff03.akb`），6,419 到 6,563（`bcg99.akb`），结束于 6,563。

名单可以被 Escape、Delete、小键盘 0 和鼠标副键提前结束（面板循环 0x4a8780 把输入编号 1、0xd3、0x52 和 0x201 送到虚表偏移 0x80 的函数 0x480ff0，即地址 0x530180 的槽），但只在全局变量 55 的第 11 位已置位时有效（0x480ff0 从脚本变量记录的偏移 0x6e4 读它，即第 55 条、每条 32 字节的记录；脚本在游戏开始时置位第 11 位，在标题画面清除）。该位为 0 时名单无法被中断。鼠标主键点击（编号 0x200）、Enter、空格和跳过模式都不起作用：点击和 Enter 只会送给面板的按钮，而它没有按钮，循环里也没有对跳过模式的判断。被中断时，处理函数把面板的结果设为 1（偏移 0x8 和 0xc 的两个字段：类型 0、值 1）并停止循环；时间用完时结果保持开始时的值 0。面板的销毁方式相同（0x480e80、0x480e20），此外什么都不变：没有标志、没有声音、没有变量。`Game.990` 压入这个结果（0x492160 用 0x4722f0 复制，用 0x4589c0 压入）：名单播完时是 0（完整播放的轨迹里是 0，随后是淡入的 `Screen.0(16,0)`），被提前结束时是 1。脚本随后自己补画最后一屏（返回 1 时脚本用 `Game.12` 记录 `ending.akb` 和 `staff03.akb`）这一点是从脚本推断的，不是从代码读出的。运行时在 `Game.990`（`games/apeiria/staff.rs`，`Session::roll_cancel`）里完成这一切：把图片放到特效舞台上，让画面保持实时地等待 105,000 毫秒，只在第 11 位置位时允许 Escape、Delete、小键盘 0 或鼠标副键结束等待（主键点击和跳过模式不行），并在等待结束后压入返回值。音乐不受影响，由脚本在调用之前启动。
