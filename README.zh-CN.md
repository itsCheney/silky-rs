# silky-rs

[English](README.md) | 简体中文

用 Rust 重新实现的跨平台 Silky's 引擎（SILKY'S PLUS 与 elf 自 2014 年起使用的 "Silky Engine"）。它直接读取原版游戏文件，需要你自己持有游戏。

首个目标游戏是《ふゆから、くるる。》2026 年国际版 1.0.1.0。第二个是《きまぐれテンプテーション2》（2024 年日文版，已打 1.02 补丁），界面已部分完成。桌面端首先支持 Windows。

## 进度

还在早期。目前可用的部分：

- `.arc` 封包，包括 LZSS 压缩，以及 `Patch.xml` 或 `FileInfo.xml` 规定的覆盖顺序（`script.arc;script1.arc`：后面的封包优先）。`update.arc` 作为最新的数据封包读取。
- 以散文件形式放在封包旁目录中的汉化补丁（`<名称>_chs`：GBK 编码的脚本和重绘的图片），作为一种语言来选择。
- AKB 图片，包括叠加在基础图上的 `AKB+` 差分图。
- `.MAP` 文本表（每种语言一个分区）。
- `.MES` 脚本与 `LIBLARY.LIB`：文件头、偏移表和完整的字节码解码。日文版的文本直接写在脚本中（换行由 `text` 指令表示）。
- `.VSD` 视频容器（内部是 MPEG-1 程序流）。
- 脚本虚拟机：栈、变量区、函数、脚本调用和选项。引擎函数交给宿主处理。
- 第一批引擎函数和软件渲染器：背景、事件 CG 及其差分、带表情的立绘、对话框及其名牌、头像和文本、本地化文件名、标题画面图片。
- 引擎自绘的界面：标题菜单按钮（布局取自可执行文件，按语言区分）、对话框的按钮栏和图标（`mes_o.area`）、等待点击的指示图标，以及选项（`Game.20`）。
- 桌面播放器：单击或回车继续，右键隐藏对话框，鼠标滚轮打开回想，Esc 关闭画面，自动和快进模式，标题菜单和选项。
- 声音：音乐（按 WAV 文件中 `smpl` 的循环点循环）、音效和语音，由软件混音；桌面播放器通过 cpal 播放。
- 时间与转场：定时等待（点击可跳过）、淡出到某种颜色和淡入、图片与立绘的交叉淡化、使用游戏 `NN.bin` 遮罩的规则转场、画面震动，以及等待声音播放结束。时间目前暂按 1/60 秒一帧计算。
- 存档和读档画面，按引擎的方式绘制（`saveload.area` 及其图片）：手动存档、自动存档和快速存档三个分页，缩略图、日期、最新存档标记，覆盖存档、删除单个或全部存档，取自 `saveloadhelp.map` 的提示文字，以及带“下次不再显示”的确认对话框。出现选项时自动存档；“继续游戏”读取最新的存档。存档是本运行时自己的 JSON 文件，每个存档附一张 PNG 缩略图。
- 回想（`backlog00.area`）：最近 300 条消息及其名牌，重播某句的语音，依次播放勾选的语音，以及跳回某条消息。
- 设置画面（`config00.area`、`config01.area`），可从标题菜单、对话框的设置按钮或右键打开：文字速度、逐字显示及句读后的停顿、快进（仅已读文本、速度、选项后继续）、自动播放、对话框颜色和不透明度、特效速度、各类确认对话框、右键功能、语言（游戏中即可切换），以及总音量、音乐、音效、语音和每个角色语音的音量。提示文字取自 `confighelp.map` 和 `soundconfighelp.map`。
- 标题菜单的鉴赏模式：CG 鉴赏（`cgmode.area`，九页缩略图，点击可依次浏览一组图片）、剧情回放（`scmode.area`）和音乐鉴赏（`soundmode.area`，带播放进度条）。解锁记录与设置一起保存在存档文件夹的 `system.json` 中：剧情中出现过的图片和音乐，以及读过的文本。CG、剧情和曲目的列表取自《ふゆから、くるる。》的可执行文件。
- 视频（`.vsd`）：MPEG-1 视频和 MP2 音频由 [pl_mpeg](https://github.com/phoboslab/pl_mpeg)（MIT，位于 `crates/silky-runtime/vendor`）解码；画面跟随声音的时钟，点击可结束视频。
- 对话框的“上一个选项”按钮（回到上一个选项前的那句话）和“下一个选项”按钮（快进到下一个选项，未读文本也会跳过）。
- 输出分辨率与游戏的 1280 x 720 布局分开：图片按游戏原尺寸合成后一次放大，文字按输出尺寸绘制（播放器为窗口高度，`silky-run snap` 默认 1080，可用 `--height` 修改），因此文字保持清晰。点击和区域判定仍使用游戏像素。
- 特写与立绘动作（依据引擎中的处理代码）：事件 CG 的移动和放大（`Game.12` 子命令 4、5），立绘的跳动或左右摇晃（`Game.13` 子命令 7；每步 50 毫秒为推测值）、换到另一个位置（子命令 10）以及偏离站位显示（子命令 14）。

在《ふゆから、くるる。》上，全部 56 个脚本（约 790 万条指令）都能解码，所有跳转都落在指令边界上；全部 3,255 张图片都能解码。在无界面模式下，虚拟机能从 `start.mes` 启动，依次走过 logo、注意事项和标题脚本，并从 `fk001.mes` 开始执行剧情，三种语言的文本都能取到。

在《きまぐれテンプテーション2》上，全部 64 个脚本和 712 张图片都能解码。在无界面模式下，`silky-run trace` 能启动到标题菜单并执行剧情，带说话人名字，支持日文；有汉化补丁目录时也支持简体中文。每个游戏都会给引擎加上自己的命令（原生类 29）；本作中哪些命令有返回值，是从它的可执行文件中读出来的。播放器和 `silky-run snap` 可以打开它：标题菜单、带说话人名牌的对话框（汉化补丁重绘的中文名牌也能用）、对话框按钮、侧边菜单、选项、行动菜单以及地图（包括第二张地图的子面板），都用游戏自带的图集绘制；对话框、行动菜单和地图的布局取自可执行文件，文字位置按游戏截图对齐。回想、存档读档、设置和确认对话框都已是游戏自己的样式，帮助文字取自游戏的 `.HLG` 表，声音页使用本作的九个角色语音分组。换装画面、搜查笔记（捜査手帳）和收集品（収集品）用各自的图集绘制，并按可执行文件的方式读取脚本的字节变量：字节 `900 + i` 非零时笔记第 `i` 条解锁，字节 `801 + i` 非零时收集品第 `i` 件解锁；服装是字节 701（形态）和 708（服装切换），关闭画面时写回；字节 711 和 712 解锁形态 C 和 D。从标题菜单打开笔记时读取脚本写在 `1000 +` 处的副本；从 1000 号起的字节变量保存在游戏之外的 `system.json` 中，读档和重新开始都不会丢失。部分笔记条目会随剧情增长：字节 `940 + i` 表示已解锁几段，其余文字被截掉，最新一段前面有“New”标记（截断和标记位置取自可执行文件）；从标题菜单打开过该条目后标记消失（字节 2020 + i）。最后一件收集品是一段语音记录，图片上是播放/暂停按钮，依次播放五个语音文件；可执行文件中的文件名是 `kt_*.ogg`，测试用的这份游戏里没有这些文件，因此会报告为缺失。在行动菜单或地图处存档时，存的是它之前的那句对话。尚未实现：两行文字的行距、循环语音和跳过未读文字，以及八段 E-mote H 场景动画（`hg030100_*.psb`）。安娜莉丝的立绘是 E-mote 4 模型（`.psb`，文件头加密）：每套服装两个文件，`ta`/`tb` 加形态和服装编号（正是换装画面所选的那些），`_h0007` 含表情 0 到 7，`_h0813` 含表情 8 到 13。[Eluna](https://github.com/xmoezzz/eluna)（放在 `vendor/eluna_rs`，MPL-2.0，与 siglus_rs 所用的是同一份）负责解密并运行时间轴和物理，它输出的精灵（带纹理的三角形、六种混合模式、模板遮罩；DXT5 纹理）在播放器中由 wgpu 绘制，无界面模式下由一个小型软件光栅器绘制，两者结果相同。本作的密钥已内置；其他游戏由运行时搜索一次全部 2^32 个密钥（几秒到一分钟）。`Game.10` 的含义读自可执行文件：子命令 6 载入一套服装，7 设置表情和表情之后的那条时间轴，13（和 12）设置姿势，16 设置 `a` 时间轴，9 和 11 显示和隐藏。模型在屏幕上的位置暂定（居中，每个模型单位 0.35 游戏像素）；有语音时嘴巴只是按固定节奏开合，没有跟随音量；GPU 绘制时动画每秒 30 帧（软件绘制时 15 帧）。在设置中关闭 E-mote 动画后画面保持静止。不带默认的 `emote` 特性编译时，这些画面会被省略。

尚未完成：其他特效。“固定文字框”设置会被保存，但不起作用，因为这里的对话框本来就不会移动。`silky-run snap` 会列出运行时尚未执行的所有引擎调用。

已与原版截图（Windows，简体中文）对照：对话框、名牌、对话框头像、中文文本的位置和字距，以及立绘的大小和位置。仍为暂定：英文文本的字体度量、两行文本的行距、换行宽度，以及选项在画面上的位置。

## 结构

| Crate | 内容 |
| --- | --- |
| `silky-format` | 文件格式。不含平台相关代码。 |
| `silky-vm` | 字节码解释器。引擎函数交给宿主处理。 |
| `silky-runtime` | 基于场景模型的引擎函数和软件渲染器。不含平台相关代码。 |
| `silky-tool` | 查看游戏目录的命令行工具。 |
| `silky-run` | 无界面运行器：记录引擎调用，或把画面保存为 PNG。 |
| `silky-player` | 桌面播放器（winit；画面由软件合成，经 wgpu 缩放显示，E-mote 也由 wgpu 绘制）。 |

`silky-runtime::Session` 持有一个运行中的游戏（解释器、运行时、渲染器和界面），接收指针、按键和时钟输入；桌面播放器以及以后的嵌入方式只负责转发输入并显示它的画面。

## silky-player

```sh
silky-player <游戏目录>                    # 游戏的第一种语言
silky-player <游戏目录> --lang zh-hans     # 简体中文（或 1）
silky-player <游戏目录> --font msyh.ttc --font arial.ttf
```

存档保存在 Windows 的 `%APPDATA%\silky-rs\<游戏目录名>`（macOS 为 `~/Library/Application Support/silky-rs/...`，其他系统为 `~/.local/share/silky-rs/...`），可用 `--saves <目录>` 指定其他位置。不指定 `--font` 时，播放器会先在 Windows 字体目录中查找游戏设置里使用的字体（Arial、微软雅黑、微软正黑体），再查找 macOS 和 Linux 上的常见字体。单击、回车或空格继续；右键隐藏对话框（可在设置中更改）；Esc 关闭画面或结束视频。播放器通过 wgpu（Metal、Vulkan、D3D12）显示画面；加 `--software`（或机器没有可用的 GPU）时改为软件缩放。

## silky-tool

```sh
silky-tool info  <游戏目录>                      # 封包与文件数量
silky-tool check <游戏目录> [--images]           # 解码全部脚本、MAP 和图片
silky-tool dis   <游戏目录> FK001.MES            # 反汇编脚本
silky-tool map   <游戏目录> FK001.MAP --section 1
silky-tool akb   <游戏目录> TITLE_BG_01.AKB title.png
silky-tool ls      <封包.arc>
silky-tool extract <封包.arc> <输出目录>
```

## silky-run

```sh
silky-run trace <游戏目录>                           # 启动过程，直到标题菜单
silky-run trace <游戏目录> --result 29.110=1         # 在标题菜单选择“开始”
silky-run trace <游戏目录> --result 29.110=1 --text-only --lang zh-hans --max-calls 50000
silky-run trace <kimaten2 目录> --result 29.110=1 --result 29.42=1,2 --result 29.43=1 --text-only
```

```sh
silky-run snap <游戏目录> --out snaps --font DejaVuSans.ttf --lines 0,10,50
silky-run snap <游戏目录> --lang 1 --font msyh.ttc --lines 170
silky-run snap <游戏目录> --lines 99999999 --path 0,1,1   # 把一条路线玩到结局
```

`snap` 用 `silky-runtime` 运行游戏，把标题画面和指定的对话行（从游戏第一行开始计数）保存为 PNG。字体不属于游戏文件，需要用 `--font` 传入一个或多个字体，按回退顺序排列；不提供字体时画面中不绘制文本。`--path` 按顺序给出前几个选项的选择（之后的选项按 `--choose`）；指定它时，游戏回到标题画面即停止运行，并且会保存每段视频结束后停留的画面。在《ふゆから、くるる。》中，`--path 1` 和 `--path 0,0` 通往两个坏结局，`--path 0,1,0` 和 `--path 0,1,1` 通往真结局，包括片尾视频和结束画面。在《きまぐれテンプテーション2》中，`--actions` 指定前几个行动菜单要选的按钮（之后的菜单轮流选择尚未完成的按钮），地图则前往第一个尚未完成的地点；前五个菜单和地图会保存为 `actionsN.png` 和 `mapN.png`。本作的调查需要在选项中选对答案，`--path` 和 `--choose` 并不知道答案，因此可能会在某个调查中绕圈。

`trace` 不执行任何引擎函数，只记录每次调用及其参数。脚本会用到返回值的调用默认返回 0，可以用 `--result 类.子命令=值` 指定；给出多个值时（`29.42=1,1,2`），后续的调用依次取用，最后一个值一直保留。选项（`Game.20`）由 `--choose` 决定，从 0 开始计数（默认第一个）。`--lang` 可取 `en`、`zh-hans`、`zh-hant` 或 `ja`（0、1、2 仍表示 `.MAP` 的分区）；每个游戏只提供它有文本的语言：《ふゆから、くるる。》为英文和简繁中文，《きまぐれテンプテーション2》为日文，存在 `kimaten2_chs` 目录时另有简体中文。在《きまぐれテンプテーション2》中，`29.42` 回答行动菜单，`29.43` 回答地图。

## 项目规则

- 游戏数据不进入仓库：图片、脚本、声音、可执行文件和转储都不提交。测试使用在代码中构造的小文件。
- 引擎行为从游戏自身的文件中获得，必要时阅读引擎的可执行文件。运行时既不需要也不加载可执行文件，复制保护不在本项目范围内。
- 未知的操作码和引擎函数会连同参数一起报告，绝不为了让脚本继续运行而当作成功处理。
